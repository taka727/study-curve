# 401 vs 403

## ✅ Can you recall it? (before reading)

> Think of the answers to the examples before reading the answer below.

**Example 1** You call an API that only members can use, without logging in. Do you get 401 or 403?

**Example 2** You log in as a regular member and call an API that only administrators can use. What do you get?

**Example 3** You got 403 in Example 2. If you log in again as the same member, without any change to that member's permissions, will the request go through?

## 🎯 Answer — remember this

- **OK**: **401 means "authentication required" (credentials missing or invalid)**; **403 means "understood, but refused"** (often used when a logged-in member lacks permission)
- **Why**: With 401, sending valid credentials may let the request through. With 403, sending it again as the same member won't help unless the permissions change (403 alone does not mean the user's identity is confirmed)

Source: RFC 9110 (15.5.2 401 Unauthorized, 15.5.4 403 Forbidden)
