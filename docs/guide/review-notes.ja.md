# 復習ノートの書き方

[English](review-notes.md) ／ [README に戻る](../../README.ja.md)

## このガイドについて

Study Curve の価値の半分は、ノートの型にある。読む前に思い出す問い、1〜2行の答え、☆◯△✗ の基準の3つ。
このガイドは、その考え方と書き方をまとめたもの。内蔵の型でノートを書く人と、自分の型を作る人の両方に向けている。

内蔵の型のノートは、コマンド「復習ノートを作成」（またはボードのデッキのカードの「＋ ノート」）で作られる。

## 考え方

- **1ノート＝思い出す1つのまとまり。** 1つのノートで確かめるのは、言えたかどうかを判定できる1つのこと
- **読む前に思い出す。** 答えを読んでから「知っていた」と思うのは、思い出したことにならない。先に問いを見て、答えを頭の中で言ってから、答え合わせを読む
- **採点は手応えではなく事実で決める。** 「なんとなく覚えている」ではなく、「答え合わせの太字を言えたか」で決める

## 内蔵の型の各部分

```markdown
# {{title}}

## ✅ 思い出せるか（読む前に）

> 例を見て答えを思い浮かべてから、下の答え合わせを読む。

**例1**

**例2**

**例3**

| 判定 | 基準 | 次回 |
|---|---|---|
| **☆ 初見** | この内容を学ぶのが初めて | 3日後 |
| **◯** | 答え合わせの太字を自分の言葉で言えた | ステージ +1 |
| **△** | 太字は言えたが「なぜ」が出てこない | 据え置き |
| **✗** | 一度学んだはずなのに出てこない | 翌日 |

---

## 🎯 答え合わせ — これを覚えていればOK

- **OK**：
- **なぜ**：
```

| 部分 | 役割 |
| --- | --- |
| ✅ 思い出せるか（読む前に） | 問いを置く場所。ここを読んで、答えを頭の中で言う |
| 例1〜3 | 問い。同じ答えを違う角度から聞く（下の「問いの作り方」） |
| 判定表 | 採点の基準。ボタンを押す前に見る。設定で間隔を変えている人は「次回」を書き換えてよい |
| 区切り線（`---`） | 問いと答えを分ける。スクロールしないと答えが見えない位置に答えを置くため |
| 🎯 答え合わせ | 答え。OK 行が採点の基準で、なぜは △ の基準 |

型そのものを変えたいときは、ファイルに写して直し、設定「復習ノートのテンプレート」に指定する。`{{title}}`・`{{deck}}`・`{{date}}` が置き換わる。

## 問いの作り方

1. **問いに答えを書かない。** 答えは「答え合わせ」の節にだけ書く
2. **定義を聞かずに、場面で聞く。** 試験も実務も、場面から答えを選ぶ形で問われる
3. **例は2〜3個。同じ答えを違う角度から聞く。** 具体的な場面、逆向き、取り違えやすいものとの対比
4. **答えが1つに決まる問いにする。** 「〜について説明せよ」は、言えたかどうかを判定できない
5. **例は短く1〜2行にする。** 読むのに時間がかかる問いは、復習のたびに負担になる

| 悪い例 | 良い例 | 理由 |
| --- | --- | --- |
| `401 とは？` | `ログインせずに、会員だけが使える API を呼んだ。返るのは 401 と 403 のどちら？` | 定義の暗唱ではなく、場面から選ぶ |
| `401 は認証エラー。403 は？` | `一般の会員としてログインし、管理者だけが使える API を呼んだ。返るのは？` | 問いの中に答えの半分がある |
| `HTTP のステータスコードについて説明せよ` | （ノートを分け、401 と 403 の違いだけを聞く） | 範囲が広く、言えたかどうかを判定できない |

## 答え合わせの書き方

- **OK 行は1〜2行。** これを言えれば ◯ という基準になる。3行を超えるなら、ノートを分ける
- **太字にした語が採点の基準。** 太字は、言えたかどうかを判定できる語（用語、数値、コマンド）にする
- **なぜは1行。** △ の基準（太字は言えたが、なぜが出てこない）に使う
- 補足（図、出典、関連するノートへのリンク）は、答え合わせの下に自由に足してよい。ただし OK 行を長くしない

## ☆◯△✗ の振り分け

上から順に当てはめる。

| 順 | 問い | 当てはまれば |
| --- | --- | --- |
| 1 | この内容を学ぶのは初めてか（まだ覚えようとしたことがない） | ☆ 初見（ステージ据え置き、3日後） |
| 2 | 答え合わせを読む前に、OK 行の太字を**すべて**自分の言葉で言えたか | 言えなければ ✗（ステージ 0、翌日） |
| 3 | 「なぜ」も言えたか | 言えなければ △（据え置き） |
| 4 | 1〜3 のどれでもない | ◯（ステージ +1） |

- 太字の一部しか言えなかったときは ✗。太字が多くて毎回一部が抜けるなら、ノートを分けるサイン
- 例のどれかに答えられなくても、OK 行の太字と「なぜ」を言えれば ◯ でよい（順2・3 を満たしている）。例は太字を思い出すきっかけ。太字は言えても「なぜ」が出てこなければ、順3 のとおり △

### 「迷ったら△」をやめる理由

- △ はステージを**据え置く**。安全な選択に見えるが、どちらに外れても損をする
  - 本当は忘れていたのに △ → 間隔が短く戻らず、忘れたまま次の復習まで空く
  - 本当は言えていたのに △ → 間隔が伸びず、同じノートが同じ間隔で出続ける。毎日の件数が減らない
- 迷うのは、基準が手応え（自信）になっているから。基準を「OK 行の太字を言えたか」に置けば、迷う余地は小さい
- ✗ は罰ではない。翌日にもう一度出るだけで、そこで言えれば ◯ で進む

## ノートを分ける目安

次のどれかに当てはまったら、ノートを分ける。

- OK 行が3行を超える
- 太字が4つを超える
- 例どうしの答えが違う（1本のノートで2つのことを聞いている）

逆に、1つの用語の言い換えだけなら、1本にまとめる。

## 実務メモから作る

1. メモから「次に同じ場面が来たときに、調べずに判断したいこと」を1つ選ぶ
2. それを OK 行（1〜2行）に書く。太字は判断の決め手になる語（`git revert`、`git reset` など）
3. その判断が必要になる場面を、例1〜3 として問いの形に書く（メモの状況をそのまま使うと書きやすい）
4. 理由を「なぜ」に1行で書く
5. メモの残り（手順の詳細、ログ、リンク）は、答え合わせの下か元のメモに残す。復習ノートに全部は入れない

元のメモの例（架空）：

```markdown
- 本番に出した修正が不具合。push 済みだったので reset はやめて revert した
- 手元の直前のコミットは reset --soft HEAD~1 でやり直した（変更は残る）
- reset して force push すると、取り込んだ人の履歴と食い違う
```

このメモから作ったのが、下のサンプル「push 済みのコミットを取り消す」。

## サンプル

| サンプル | 見どころ |
| --- | --- |
| [401 と 403 の違い](../examples/ja/401-vs-403.md)（資格の暗記用） | 例1 と例2 は対比、例3 は逆向き（403 からの判断）。どれも OK 行の太字で答えられる |
| [push 済みのコミットを取り消す](../examples/ja/git-undo-pushed-commit.md)（実務メモから） | 上の元のメモの3行から、判断の決め手（revert と reset）だけを OK 行にした。手順の細部は入れていない |

- デッキのフォルダに写すと、ボードの「未登録のノート」に出る。そこから登録する（`study-*` を書いていないので、置いただけでは登録されない）
- サンプルは書き終えた例なので、テンプレートには使わない（プレースホルダーがなく、作るたびに同じ本文になる）。型として使うのは「内蔵の型の各部分」の全文

## 自己チェックにチェックボックスを使う場合

内蔵の型はチェックボックスを使わない。使いたい人は、例の行を `- [ ] 例1 …` にし、設定「採点したら本文のチェックを外す」を ON にする。

- 採点すると、設定「チェックを外す見出し」（既定 `思い出せるか`）を含む見出しの下の完了チェック（`- [x]`）だけが `- [ ]` に戻る。ほかの見出しの下、frontmatter、コードブロックの中は変わらない
- 見出しを英語などで書く人は、この設定を自分の見出しに合わせる

## 生成 AI で作る場合

どのツールでも使える指示文の例：

```text
次の内容から、復習ノートを1本作ってください。

- 形は下の「型」のとおりにする（見出し、例1〜3、判定表、答え合わせ）
- 「思い出せるか」の例は、答えを含まない問いにする。定義ではなく、場面から答えを選ぶ問いにする
- 答え合わせの OK 行は1〜2行。言えたかどうかを判定する語を太字にする
- 「なぜ」は1行
- frontmatter（--- で囲んだ部分）は書かない
- 覚えることが3つ以上あるなら、ノートを分ける案を先に出す

型：
（内蔵の型をここに貼る）

内容：
（教材やメモの該当部分をここに貼る）
```

- 答えの正しさは、教材や公式の資料で必ず確かめる（生成された答えが誤っていることがある）
- 仕事のメモなど、外に出せない内容を貼らない。どのサービスに何を送るかは使う人が決める（このプラグインは外部と通信しない）
- 作ったノートは、ボードの「未登録のノート」から登録するか、「復習ノートを作成」で作ったノートに本文を貼る

## frontmatter について

自分で書かなくてよい。登録とノートの作成のときに、プラグインが書く。使用中のノートの frontmatter は、たとえば次のようになる。

```yaml
---
study-deck: 資格の勉強
study-next: 2026-10-20
study-stage: 2
study-history:
  - 2026-10-10 ok
  - 2026-10-13 ok
---
```

キーの意味と書式は README の [frontmatter の仕様](../../README.ja.md#frontmatter-の仕様) が正本。手で直すときは、次に気をつける。

| したいこと | 直し方 | 注意 |
| --- | --- | --- |
| 次の復習日を変える | `study-next` を `YYYY-MM-DD` で書き換える（ボードの「明日に送る」でもよい） | 形式が正しくないと未設定として扱われ、今日の復習に出る |
| しばらく出さない | コマンド「このノートの復習を休止／再開」（`study-suspended: true`） | 手で書くときは `true`（引用符なし） |
| デッキを変える | `study-deck` を書き換える | 設定にない名前だと、ボードに「設定に無いデッキ名です」と出る |
| ステージを変える | `study-stage` を整数で書き換える | `"3"` のように引用符で囲むと 0 として扱われる |
| 履歴 | 手で直さない | 直近20件だけを残す。書式は README の表のとおり |
| 復習をやめる | コマンド「このノートを復習対象から外す」 | 5つのキーがすべて消える（ステージと履歴も） |
