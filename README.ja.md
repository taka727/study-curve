# Study Curve（学習カーブ）

[English](README.md)

エビングハウスの忘却曲線に沿って、**ノート単位**で復習日を管理する Obsidian プラグイン。
登録したノートは、思い出せたら固定の間隔の段（既定は 1, 3, 7, 14, 30, 60, 90 日）を1つずつ上がり、忘れたら最初に戻る。
試験日の決まった勉強なら、デッキに試験日を入れると、試験を越える予定を手前に寄せ、直前の数日はデッキのノートをすべて出す。

ほかにも Spaced Repetition（フラッシュカードとノート全体）や Note Review Reminder（間隔を空けた復習とリマインダー）など、ノートの復習を予定するプラグインがある。
Study Curve の特徴は、1つのノートを「思い出せるべき1つの話題」として扱うこと、復習の状態を各ノートの frontmatter だけに持つこと、内蔵の型で「思い出せるか」の問いと判定の基準をノートに入れられること。

## 機能

- ノート単位の復習。☆ ◯ △ ✗ の4つで採点し、次の復習日が決まる
- 復習ボード：デッキごとの状況、今日の復習、これからの復習量、未登録のノート
- 試験日による前倒しと、直前の総ざらい（試験日は入れなくても使える）
- デイリーノートに貼るブロック（`study-today`・`study-forecast`・`study-progress`）で、ボードを開かずに採点できる
- 「復習ノートを作成」で、内蔵の型（または自分のテンプレート）からノートを作り、そのまま登録する
- デッキのフォルダにある既存のノートを、件数を確かめてからまとめて登録する
- Mac・Windows・iPad・スマホで同じ操作。画面の幅に合わせて表示が変わる

## 仕組み

### 間隔の決まり方

ステージごとに固定の間隔を持ち、採点でステージを動かす。

| ステージ | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 次回まで | 1日 | 3日 | 7日 | 14日 | 30日 | 60日 | 90日 |

- **◯ 覚えてた** → ステージ +1（最終ステージで頭打ち）
- **△ あいまい** → ステージ据え置き（同じ間隔でもう一度出る）
- **✗ 忘れた** → ステージ 0 に戻る（翌日また出る）
- **☆ 初見** → ステージ据え置き。ただし**間隔は3日で固定**（ステージの間隔を使わない）

`☆ 初見` は「忘れた」ではなく「**まだ学習していない**」ための判定。忘却曲線は一度覚えたものの保持を測る道具なので、
未学習の項目に ◯△✗ を付けると「忘れた」と「そもそも習っていない」が同じ尺度に混ざり、ステージが進まない。
翌日に戻すと読んだ直後の短期記憶を測ってしまい、1週間空けると初学の内容は残らないため、その間を取って3日にしてある。

間隔は設定から変えられる。SM-2 のような ease factor は持たない。「なぜ今日これが出たのか」がステージだけで説明できるほうが、続けるときに納得しやすいため。

時計のボタン（明日に送る）は、ステージを変えずに予定を1日送る（予定日と今日のうち遅いほうの翌日）。直前の総ざらいの期間中のデッキでは出ない。

### 試験日からの逆算（任意）

デッキに試験日を入れると、次の2つが働く。入れなければ、どちらも働かない。

1. **前倒し** — 次回の予定が試験日を越える場合、試験日当日まで手前に寄せる
2. **直前の総ざらい** — 試験日まで既定で7日を切ると、そのデッキのノートは予定日に関係なく全部「今日の復習」に出る（設定の「直前総ざらいの日数」で変えられる）

## 使い始め方

1. コミュニティプラグインから Study Curve を入れて有効にする
2. リボンの脳のアイコン（またはコマンド「復習ボードを開く」）でボードを開き、案内に沿ってデッキ（資格・科目）を作る。すでに `study-deck` の書かれたノートがあれば、そのデッキを見つけて設定に取り込める
3. ノートを用意する
   - 新しく書くなら、コマンド「復習ノートを作成」か、デッキのカードの「＋ ノート」
   - 既存のノートなら、ボードの「未登録のノート」から登録するか、ノートを開いてコマンド「このノートを復習対象に登録」
4. 翌日から、ボードの「今日の復習」（またはデイリーノートの `study-today`）で採点する

## 復習ノートの書き方

「復習ノートを作成」は、次の内蔵の型でノートを作る（`{{title}}` は入力したタイトル）。

```markdown
# {{title}}

## ✅ 思い出せるか（読む前に）

> 例を見て答えを思い浮かべてから、下の答え合わせを読む。

**例1**

**例2**

**例3**

| 判定 | 基準 | 次回 |
|---|---|---|
| **☆ 初見** | この内容を学ぶのが初めて | 3日後 |
| **◯** | 答え合わせの太字を自分の言葉で言えた | ステージ +1 |
| **△** | 太字は言えたが「なぜ」が出てこない | 据え置き |
| **✗** | 一度学んだはずなのに出てこない | 翌日 |

---

## 🎯 答え合わせ — これを覚えていればOK

- **OK**：
- **なぜ**：
```

- 作る場所は、デッキのフォルダ（なければ Obsidian の「新規ノートの作成場所」）。同じ名前のノートがあれば ` 1`、` 2`… を付ける
- 設定「復習ノートのテンプレート」に自分のファイルを指定すると、内蔵の型の代わりに使う。`{{title}}`・`{{deck}}`・`{{date}}` が置き換わる。テンプレートの frontmatter は残したまま、`study-*` を足す
- 見出し「思い出せるか」は、設定「採点したら本文のチェックを外す」の対象の見出しの既定値とそろえてある

問いの作り方、答え合わせの書き方、☆◯△✗ の振り分け、実務メモや生成 AI から作る方法は、[復習ノートの書き方ガイド](docs/guide/review-notes.ja.md)にまとめた。書き終えたサンプルは [`docs/examples/ja/`](docs/examples/ja/) にある。

## コマンド

既定のホットキーは付けていない。☆ ◯ △ ✗ にはホットキーを割り当てておくと、ノートを読みながら採点できる。

| コマンド | 内容 |
| --- | --- |
| 復習ボードを開く | ボードをタブで開く |
| 今日の復習を始める（最初のノートを開く） | 今日の復習の先頭のノートを開く |
| このノートを復習対象に登録 | フォルダからデッキを判定する。判定できなければデッキを選ぶ（新しい名前なら設定にも追加） |
| 復習ノートを作成 | デッキとタイトルを選んでノートを作り、登録して開く |
| このノートを復習対象から外す | 確認してから、`study-*` を frontmatter から消す |
| 復習を記録: ◯ 覚えてた / △ あいまい / ✗ 忘れた / ☆ 初見 | 開いているノートをその場で採点する |
| このノートの復習を休止／再開 | `study-suspended` を切り替える |

## ノートに埋め込むブロック

デイリーノートや週次レビューに貼って使う。

````markdown
```study-today
deck: AWS ANS   # 省略可。デッキを絞る
limit: 10       # 省略可。既定は設定の「1日に出す上限」
```

```study-forecast
days: 30        # 省略可。既定は設定の「予定グラフの日数」
deck: AWS ANS   # 省略可
```

```study-progress
deck: AWS ANS   # 省略可
```
````

- `study-today`：ボードと同じ行が出るので、デイリーノートの中で採点まで完結できる
- `study-forecast`：今後 N 日の復習の件数の棒グラフ。遅れている分は今日に数え、今日の棒の下に赤で示す
- `study-progress`：デッキごとの試験日、登録数、今日の件数、遅延、定着度の表

## 設定

| 項目 | 既定 | 内容 |
| --- | --- | --- |
| ステージごとの間隔（日） | `1, 3, 7, 14, 30, 60, 90` | 左からステージ0,1,2…。「、」や全角の数字でも入力できる。空欄なら既定の間隔 |
| 1日に出す上限 | 20 | 0 で無制限 |
| 直前総ざらいの日数 | 7 | 試験日までこの日数を切ると、デッキのノートを全部出す |
| 予定グラフの日数 | 14 | ボードと `study-forecast` の既定 |
| 採点したら次のノートを開く | ON | ボードで採点した直後に、次のノートを開く |
| 採点したら本文のチェックを外す | **OFF** | ON にすると、下の見出しのセクションの中の完了チェック（`- [x]`）を `- [ ]` に戻す。ほかの見出しの下、frontmatter、コードブロックの中は変えない |
| チェックを外す見出し | `思い出せるか` | この文字列を含む見出しから、同じかそれより上のレベルの次の見出しの手前までが対象 |
| 復習ノートのテンプレート | （空欄） | 空欄なら内蔵の型 |
| デッキ | （なし） | 名前・フォルダ・試験日。「デッキを追加」と、各行の編集・削除のボタンで直す |

- 数値の欄に正しくない値を入れると、理由が出て保存されない
- デッキの**フォルダ**は「未登録のノートの洗い出し」と「登録時のデッキの判定」に使う。入れ子のときは、より深く一致したデッキが選ばれる
- デッキの**名前を変える**と、そのデッキのノートの `study-deck` もまとめて書き換える（件数は保存の前にダイアログに出る）。コードブロックの `deck:` と、スクリプトに書いた名前は書き換えない
- デッキを**削除する**ときは確認が出る。ノートを残すか、ノートを復習対象から外すかを選べる

## frontmatter の仕様

復習の状態はノートの frontmatter だけに持つ。プラグイン専用のデータベースを作らないので、ノートを見れば次にいつ復習するのかが分かり、Dataview からも読める。

```yaml
---
study-deck: AWS DOP      # どのデッキ（資格・科目）か
study-next: 2026-09-19   # 次の復習日
study-stage: 2           # 復習ステージ
study-history:           # 直近20回の手応え
  - 2026-09-12 ok
  - 2026-09-16 ok
study-suspended: true    # （任意）復習を一時休止する
---
```

| キー | 型 | 意味 | 書き込むとき |
| --- | --- | --- | --- |
| `study-deck` | 文字列 | デッキの名前。これがあるノートが復習対象 | 登録、ノートの作成、デッキの名前の変更 |
| `study-next` | 日付（`YYYY-MM-DD`） | 次の復習日 | 登録、採点、明日に送る |
| `study-stage` | 整数（0〜） | 間隔の段階。設定の間隔の何番目か | 登録（0）、採点 |
| `study-history` | 文字列のリスト | 採点の記録（直近20件）。`ok`＝◯、`hard`＝△、`ng`＝✗、`new`＝☆ | 採点 |
| `study-suspended` | 真偽値（省略可） | 休止中。今日の復習に出ない | 休止／再開 |

復習対象から外すと、この5つのキーをすべて消す（ほかのキーには触れない）。

## モバイル

Mac・Windows・iPad・Android で同じように使える。`isDesktopOnly: false` で、Node や Electron の API は使っていない。

端末で分けず、**そのとき実際に使える幅**で表示を変える。Android の縦画面も、iPad の分割表示も、Mac でボードをサイドバーに入れた場合も、同じ幅なら同じ見た目になる。

| 幅 | 表示 |
| --- | --- |
| 520px 未満 | 1行を縦に積み、採点のボタンを横幅いっぱいに。ボタンは記号（☆ ✗ △ ◯）だけ。予定グラフの日付は2日おき |
| 380px 未満 | 予定グラフの日付は3日おき。進捗の表は横にスクロール |
| 520px 以上 | 1行に収め、ボタンは「✗ 忘れた」など文字つき。デッキのカードは複数列 |

タッチ操作の端末では、採点などのボタンを押しやすい大きさにしている。

端末をまたぐときの注意：

- 復習の状態はノートの frontmatter にあるので、Obsidian Sync でも obsidian-git でも、ノートが同期されればそのまま引き継がれる
- **同じノートを2台で同時に採点しない。** ノートそのものの同期の衝突になる
- **「今日」は端末のローカルの日付で決まる。** 開いたまま日付が変わると、ボードとブロックは新しい日付で描き直される
- 「採点したら次のノートを開く」を ON にしていると、スマホではボードが次のノートに置き換わる。ボードを残したい場合は OFF にする

## プライバシーと開示事項

- 外部との通信はしない。すべて手元で動く
- 無料。支払い、アカウント、広告、テレメトリはない
- 読み書きするのは Vault の中のファイルだけ。ソースは公開している（MIT）

読むもの：

- 登録したノートを探すため、Vault のすべての Markdown ノートの frontmatter（Obsidian のメタデータのキャッシュから）。ノートはどのフォルダにあっても登録できるので、すべてのノートを見る。読んだ内容を Vault の外へ送ることはない
- デッキのフォルダの欄と「復習ノートのテンプレート」の欄の候補に出す、ノートとフォルダの名前
- 「復習ノートを作成」のときに、「復習ノートのテンプレート」に指定したファイル
- 「採点したら本文のチェックを外す」を ON にしたときだけ、採点したノートの本文

書き換えるもの：

- 登録したノートの frontmatter の `study-*` キー（上の表）
- 「復習ノートを作成」で作るノート（デッキのフォルダ、または Obsidian の新規ノートの作成場所）
- 「採点したら本文のチェックを外す」を ON にしたときだけ（**既定は OFF**）、指定した見出しのセクションの中の完了チェック
- まとめて登録するとき、デッキの名前を変えるとき、デッキを削除してノートを外すときは、件数を確かめてから書き込む
- 設定はプラグインのフォルダの `data.json` に保存する

## スクリプトから使う（Templater など）

```js
const plugin = app.plugins.plugins['study-curve'];
const queue = plugin.getDueQueue('AWS ANS'); // デッキ名は省略可
```

`getDueQueue(deckName?)` は、今日の復習と同じ並び（遅延 → 今日 → 直前の総ざらい）を返す。期日の判定と直前の総ざらいの条件はプラグインの中にあるので、テンプレートに同じ処理を書き写さなくてよい。

## 開発

```bash
npm install
npm run build    # 型チェック＋本番ビルド。副作用なし（自動審査と CI もこれを使う）
npm run dev      # 監視ビルド。OBSIDIAN_DEV_PLUGIN_DIR があれば確認用の Vault へコピー
npm test         # ユニットテスト（Vitest）
npm run lint     # ESLint（manifest.json の検査を含む）
npm run deploy   # main の本番ビルドを OBSIDIAN_PLUGIN_DIR（実運用の Vault）へコピー
```

`.env.example` を `.env.local` にコピーして、コピー先のパスを書く（`.env.local` はコミットしない）。

- 実運用の Vault に入れるのは `npm run deploy` だけ。deploy は main ブランチで、未コミットの変更がなく、`origin/main` と同じコミットのときだけ動く
- 作業中のブランチは `npm run dev` で確認用の Vault に入れて試す

### リリース

タグ（`v` なし。`manifest.json` の `version` と同じ）を push すると、GitHub Actions が下書きのリリースを作る（`main.js`・`manifest.json`・`styles.css` を添付）。添付ファイルを確かめてから公開する。

```bash
npm version patch   # manifest.json・package.json・versions.json を更新してコミットとタグ
git push origin main
git push origin <版>
```

修正を出すときは、必ず版を上げる（同じリリースのファイルを差し替えても反映されない）。
